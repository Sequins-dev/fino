# QUIC Conformance Matrix

This matrix tracks local evidence for the QUIC transport implementation. "Direct"
means a local test observes public behavior or an explicit `@internal` test hook.
"Delegated" means the behavior is owned by ngtcp2/ngtcp2_crypto and is not
claimed as locally proven beyond integration outcomes.

## RFC 9000 Transport

| Area | Status | Evidence |
| --- | --- | --- |
| Version Negotiation | Direct | `tests/net/quic.test.mts` and `tests/net/quic-sim.test.mts` cover unsupported-version probes, advertisement filtering, and no accept-state creation. |
| RFC 9368 compatible Version Negotiation retry | Direct | `tests/net/quic-sim.test.mts` injects a compatible Version Negotiation packet on the client path, proves the default first flight uses QUIC v1, and verifies the connection retries to negotiated QUIC v2. |
| Client Version Negotiation bad-CID rejection | Direct | `tests/net/quic-raw-packets.test.mts` injects a Version Negotiation packet with a bit-flipped DCID (does not match the client's SCID) offering a mutually-supported version. The handshake completes normally, proving the forged VN was silently discarded per RFC 9000 §6.2. |
| Client incompatible Version Negotiation failure | Direct | `tests/net/quic-raw-packets.test.mts` injects an incompatible VN (no mutually-supported version), asserts `connect` rejects with `QuicVersionNegotiationError`, then pumps one more idle turn and asserts no additional outbound datagrams were queued — proving the client failed locally without emitting a CONNECTION_CLOSE frame. |
| Initial packet size and padding | Direct | `tests/net/quic-sim.test.mts` asserts simulated Initial datagrams are at least 1200 bytes and malformed Initial probes do not create accept state. |
| Retry address validation | Direct | `tests/net/quic.test.mts` covers Retry token tamper, wrong DCID, and wrong address with Node-aligned immediate CONNECTION_CLOSE behavior for invalid Retry tokens. Simulator covers Retry response and anti-amplification behavior. Node reference: `src/quic/endpoint.cc` validates `RetryToken::kTokenMagic` and calls `SendImmediateConnectionClose` on validation failure. |
| Expired Retry token | Direct | `tests/net/quic.test.mts` obtains a Retry token, waits past the configured timeout, replays it from the original address, and verifies immediate CONNECTION_CLOSE plus retry-token rejection stats. |
| NEW_TOKEN receipt and reuse | Direct | `tests/net/quic.test.mts` proves NEW_TOKEN is persisted as address-validation state and emitted as `newtoken`, distinct from TLS `sessionticket`. `tests/net/quic-sim.test.mts` proves a server-issued NEW_TOKEN is reused from the same client address, accepted by the server, and avoids a fresh Retry after the address-validation cache expires. |
| NEW_TOKEN tamper/expiry/replay rejection | Direct | `tests/net/quic-sim.test.mts` proves tampered, expired, and wrong-IP replayed regular tokens are not accepted. |
| Node-aligned endpoint policy defaults | Direct | `tests/net/quic.test.mts` asserts resolved Fino transport defaults for busy mode, total/per-remote connection limits, Retry/regular token expiry, address-validation cache size, immutable stats, and immutable transport snapshots. |
| Node API parity | Direct | `tests/net/quic.test.mts` proves `[Symbol.asyncDispose]` closes endpoints, listeners, and connections idempotently; QUIC stream reads honor pre-aborted and mid-wait `AbortSignal`s; and accepted connection events resolve exactly once. |
| Endpoint packet diagnostics | Direct | `tests/net/quic-sim.test.mts` asserts Node-aligned packet-defense counters: `packetsBlocked` only for source filtering, packet-only accounting for Retry/VN/refusal paths, successful session packets count bytes, and session-creation rate-limit drops stay outside `packetsReceived`. Node reference: `src/quic/endpoint.cc` increments `packets_blocked` only in the block-list path and records received bytes only after `ReadPacket()` succeeds. |
| QUIC lifecycle topics | Direct | `tests/net/quic.test.mts` asserts Fino topics for Node transport diagnostics-channel equivalents: endpoint lifecycle, session lifecycle, handshake, key update, received Version Negotiation, streams, DATAGRAM send/receive/status, path validation, TLS session tickets, NEW_TOKEN, and close/error paths, including owner connection, error, stats, and handshake TLS metadata payload context where Node publishes it. |
| Transport parameter snapshots | Direct | `tests/net/quic.test.mts` exposes frozen local and remote transport-parameter snapshots after handshake, including DATAGRAM size, active CID limit, migration disablement, and flow-control limits. |
| Configurable transport parameters | Direct | `tests/net/quic.test.mts` advertises configured idle timeout, flow-control windows, stream limits, ACK-delay fields, active-CID limit clamping, and disable-active-migration flags through native and public transport-parameter snapshots. |
| Streams and flow control | Direct | Loopback tests cover stream reassembly, gaps, receive credit, stream-count unblock, multi-megabyte transfer, RESET_STREAM error-code events, and STOP_SENDING. Simulator covers reordered, duplicated, and corrupted packet delivery. |
| Stream half-close and stats | Direct | `tests/net/quic-streams.test.mts` proves FIN-side half-close preserves peer reads and exposes `finalSize` plus terminal `bytesAcked` stream stats. |
| Stream reset edge cases | Direct | `tests/net/quic-streams.test.mts` proves RESET_STREAM before data, crossing in-flight data, and after peer-consumed FIN expose the correct reader/error/EOF behavior. |
| STOP_SENDING crossing data | Direct | `tests/net/quic-streams.test.mts` proves in-flight data remains readable across STOP_SENDING and future peer writes reject after STOP_SENDING is processed. |
| Stream-level MAX_STREAM_DATA | Direct | `tests/net/quic-streams.test.mts` constrains peer stream receive credit, observes stream-level blocked state, reads to return credit, and verifies queued data plus FIN drain. |
| Unidirectional MAX_STREAMS exhaustion | Direct | `tests/net/quic-streams.test.mts` advertises a unidirectional stream limit of 3, verifies the fourth open waits, then proves it resolves after peer consumption returns credit. |
| Unidirectional stream sides | Direct | `tests/net/quic.test.mts` proves local unidirectional streams expose immediate read EOF while retaining writes, and remote unidirectional streams retain reads while rejecting writes before native queuing. Node reference: `src/quic/streams.cc` treats local unidirectional streams as never readable and remote unidirectional streams as never writable. |
| Stream source handling | Direct | Loopback tests cover QUIC stream writes from `ArrayBuffer`, `DataView`, partial typed-array views, shared-buffer-backed views, Web Streams writable chunks, and Node-aligned source-byte copying before delayed transport flush. Node reference: `src/quic/streams.cc` copies ArrayBuffer/View stream sources into fresh backing storage before queueing. |
| Connection-level flow-control unblock | Direct | `tests/net/quic-sim.test.mts` exhausts aggregate connection credit across streams, observes pending native writes, verifies blocked stream topics and events, reads across streams, and verifies all blocked writes resume. |
| Node send-drain reentrancy | Direct | Node reference: `src/quic/session.cc::SendPendingDataScope` and `src/quic/application.cc::SendPendingData`. Fino coalesces nested `_driveWrites()` calls with an in-progress guard and the existing simulator stream/DATAGRAM stress tests verify forward progress. |
| Send-path batching | Direct | `tests/net/quic-sim.test.mts` instruments simulated `sendBatch` calls and proves queued DATAGRAM packets flush through a multi-packet batch while preserving delivery. Real transports use Linux `sendmmsg`/`recvmmsg` when available, retain Darwin/other fallback loops, and `_driveWrites()` batches preallocated packet buffers before flushing. |
| Before/after QUIC throughput benchmark | Direct | `benchmarks/net/quic-loopback-transfer.bench.mts` supports single-binary bounded loopback measurement and `QUIC_BENCH_BASELINE_BIN`/`QUIC_BENCH_CANDIDATE_BIN` comparison mode that emits both results plus a throughput ratio. `research-docs/research/quic-node-transport-audit.md` records the last measured numbers. |
| Read-path batching | Direct | `tests/net/quic.test.mts` exposes `maxBatchReadPacketsPerTurn` in `__inspectQuicRuntimeTuning()`, and `tests/net/fixtures/quic/sim-harness.mts` records simulated `recvBatch` burst sizes for batch-read proof. |
| ECN metadata | Direct | `tests/net/quic-sim.test.mts` enables `transport.ecn`, passes per-packet ECN through the simulator transport, gives ngtcp2 real `ngtcp2_pkt_info` buffers, and observes outgoing ECT(0) metadata while preserving DATAGRAM delivery. `tests/net/quic.test.mts` also enables `transport.ecn` on real IPv4 UDP loopback sockets, proving the `recvmsg` ancillary-data receive path and outbound `sendmsg` traffic-class control messages preserve DATAGRAM delivery. |
| Migration and path validation | Direct | Simulator covers NAT rebinding, active migration success/failure fallback, preferred-address success, default preferred-address ignore policy, and preferred-address failure fallback. |
| DATAGRAM across migration | Direct | `tests/net/quic-sim-recovery.test.mts` sends DATAGRAM frames before and after active migration, verifies migrated-path packet delivery, sender ACK status, and peer DATAGRAM delivery. |
| Active CID limit migration rotation | Direct | `tests/net/quic-sim.test.mts` configures `activeConnectionIdLimit: 2` on both sides, performs an active migration, awaits the server `migration` event (result: success), and then verifies stream data flows via the migrated address. With limit=2, the server must retire the old CID and reissue a new one for the migration to succeed at all — proving CID rotation, retirement, and route-table update. |
| Path-validation NEW_TOKEN flag | Direct | `tests/net/quic.test.mts` asserts `QuicPathValidationEvent.newToken`. |
| Path-validation abort on close | Direct | `tests/net/quic-sim-recovery.test.mts` starts active migration, closes the connection during validation, and verifies a terminal `aborted` path-validation event for the abandoned path. |
| CID lifecycle and stateless reset | Direct | Loopback tests cover issued CID registration/removal, destination-CID reset token activation/deactivation, unknown short-packet reset, minimum reset size, rate limiting, and draining route retention. |
| Configurable CID length | Direct | `tests/net/quic.test.mts` configures 12-byte local CIDs, verifies resolved endpoint options, and observes 12-byte native destination CIDs on both peers. |
| Idle timeout | Direct | Simulator advances deterministic time and asserts connection close plus post-close operation rejection. |
| Keep-alive PINGs | Direct | `tests/net/quic.test.mts` enables `keepAliveTimeoutMs`, observes peer `stats.pingReceived`, and verifies default `keepAliveTimeoutMs: 0` does not send idle keep-alive PINGs. Node reference: `src/quic/session.cc` forwards non-zero keep-alive timeouts to ngtcp2. |
| Peer stream idle timeout | Direct | Node reference: `src/quic/session.cc::CheckStreamIdleTimeout`. Simulator covers peer-initiated stream timeout, stat increment, peer-visible stream close, and unrelated stream usability. |
| Handshake timeout | Direct | Simulator blackholes the handshake and asserts pending connect rejection without accept-state creation. |
| Connection close and draining | Direct | Loopback and simulator tests cover peer-visible application close, injected peer transport/protocol-error close, post-close operation rejection, closing-period CONNECTION_CLOSE retransmission with backoff, route retention during draining, custom `drainingPeriodMultiplier` retention, and no reset for late known-CID packets. ## RFC 9001 TLS And Packet Protection

| Area | Status | Evidence |
| --- | --- | --- |
| TLS 1.3 integration and ALPN | Direct | Loopback tests cover successful QUIC handshakes, raw `h3` ALPN negotiation, and ALPN mismatch failure. |
| Handshake diagnostics metadata | Direct | `tests/net/quic.test.mts` asserts `quic.session.handshake` topics include Fino connection/address fields plus Node-aligned TLS metadata fields: protocol, server name, cipher fields, verification error fields, and early-data booleans. Backend-unavailable TLS details are reported as `null`. |
| Fino boolean peer verification | Direct | Node reference: `lib/internal/quic/quic.js` supports `strict`/`auto`/`manual`; Fino intentionally exposes only `verifyPeer: true/false`, with loopback coverage for false accepting and true rejecting the self-signed fixture. |
| TLS CA trust options | Direct | `tests/net/quic.test.mts` pins the self-signed fixture as a CA from both a file and in-memory PEM, then verifies a `verifyPeer: true` client completes with successful peer verification. |
| mTLS client certificates | Direct | `tests/net/quic.test.mts` covers `verifyClient` listeners with CA trust, closes anonymous clients, accepts clients with certificate/key material, and exposes peer verification plus peer-certificate DER bytes. Also covers `rejectUnauthorized: false` which allows the handshake to complete when a client cert fails CA verification while still surfacing the peer cert. GnuTLS backend wires the same behavior via `GNUTLS_CERT_REQUEST` vs `GNUTLS_CERT_REQUIRE` controlled by `configureGnutlsServerMtls`. |
| Per-SNI server TLS contexts | Direct | `tests/net/quic.test.mts` covers OpenSSL per-SNI context selection with wildcard matching, SNI-specific ALPN negotiation, and servername handshake metadata. Runtime `setSNIContexts()` is tested by rebuilding contexts mid-listener and verifying a new connection uses the updated cert (ALPN proof). GnuTLS per-SNI contexts remain deferred (OpenSSL-only by design). |
| TLS supported groups | Direct | `tests/net/quic.test.mts` validates the `tlsGroups` option, constrains both loopback peers to `X25519`, and verifies invalid OpenSSL group names fail during TLS context creation. OpenSSL is implemented through `SSL_CTX_ctrl(..., SSL_CTRL_SET_GROUPS_LIST, ...)`; GnuTLS group constraints remain deferred. |
| Node peer verification policy modes | Intentional Divergence | `strict`/`auto`/`manual` are not exposed in this Fino transport phase to preserve the existing public API shape. |
| Node callback destruction semantics | Intentional Divergence | Node routes QUIC callback throws through `safeCallbackInvoke` lifecycle error handling. Fino exposes QUIC through EventTarget, whose listener errors are isolated by design; `tests/net/quic.test.mts` documents that later QUIC listeners still run after a listener throws. |
| Packet protection, header protection, key derivation | Delegated | Implemented through ngtcp2/ngtcp2_crypto; local tests observe encrypted handshakes, corrupted-packet drop/retransmit, and key update continuity. |
| Key update | Direct | Loopback and simulator tests initiate local and peer key updates and verify stream traffic continues. |
| Key-updated traffic under loss | Direct | `tests/net/quic-sim-recovery.test.mts` performs repeated legal key updates separated by successful bulk stream traffic and verifies both epochs survive deterministic lossy simulator delivery. |
| Parsed TLS keylog validity | Direct | `tests/net/quic.test.mts` parses a `CLIENT_HANDSHAKE_TRAFFIC_SECRET` keylog line and verifies the SSLKEYLOGFILE label, 32-byte client-random hex field, and byte-aligned hex secret. |
| Session tickets and 0-RTT | Direct | Loopback tests cover session ticket persistence, accepted/rejected early data, ALPN scoping, expiry/version rejection, byte caps, streams, and DATAGRAM early-data marking. Simulator covers Node-style deferred resumed ClientHello until first early stream/DATAGRAM operation. |

## RFC 9002 Recovery

| Area | Status | Evidence |
| --- | --- | --- |
| PTO recovery | Direct | Simulator drops the first flight and observes handshake completion after retransmission. |
| Retransmission behavior | Direct | Simulator observes corrupted stream packets being retransmitted. |
| Sustained-loss recovery | Direct | `tests/net/quic-sim.test.mts` transfers 4MiB over a deterministic 6% lossy link, verifies full stream delivery, and asserts ngtcp2 reports lost packet/byte and RTT/congestion stats. |
| Blackhole recovery and RTT stats | Direct | `tests/net/quic-sim-recovery.test.mts` applies a temporary simulated blackhole, restores the path, completes stream transfer, verifies RTT is within tolerance of the simulated latency, and asserts cwnd remains collapsed at or below ssthresh after recovery. |
| Loss detection math | Delegated | Core loss detection math remains delegated to ngtcp2; local sustained-loss and corrupted-packet tests prove the integration observes recovery and loss accounting. |
| Congestion control and ACK delay | Direct | `tests/net/quic-sim.test.mts` selects cubic, reno, and bbr through endpoint options, completes stream traffic for each algorithm, and verifies native congestion-window stats are populated. ACK-delay algorithm internals remain ngtcp2-owned. |
| ACK-frequency threshold effect | Delegated | `unacknowledgedPacketThreshold` is forwarded to ngtcp2's `ack_thresh` field in `ngtcp2_settings` (struct offset 96). Behavioral effect requires the ACK Frequency draft extension (draft-ietf-quic-ack-frequency) to be negotiated via the `min_ack_delay` transport parameter; fino does not currently negotiate the extension. ACK elicitation behavior is delegated to ngtcp2. |

## RFC 9221 DATAGRAM

| Area | Status | Evidence |
| --- | --- | --- |
| DATAGRAM negotiation and sizing | Direct | Loopback and simulator tests cover negotiated support, peer max frame size, oversized rejection, and zero-length payloads. |
| Delivery and status events | Direct | Tests cover delivery, ACK, loss, abandoned status, drop-newest/drop-oldest overflow behavior, and correlation between returned `sendDatagram()` IDs and status events/topics. |
| DATAGRAM source handling | Direct | Loopback tests cover UTF-8/hex/base64 string sources, promises, `ArrayBuffer`, `DataView`, partial typed-array views, shared-buffer-backed views, and source-byte copying before queueing. |
| Non-retransmission | Direct | Simulator drops a DATAGRAM and asserts no payload retransmission. |

## External Interop And Deferred Scope

| Area | Status | Evidence |
| --- | --- | --- |
| Raw QUIC and `h3` ALPN interop | Direct | `tests/net/quic-hq.test.mts` and `tests/net/quic-node-interop.test.mts` pass when configured tools are available. |
| Large raw QUIC Node interop | Direct | `tests/net/quic-node-interop.test.mts` uses the shared `interop-harness.mts` to run a gated 1MiB bidirectional raw `h3` stream scenario against Node QUIC when `NODE_QUIC_BIN` is configured. |
| Node interop DATAGRAM scenario | Missing | The gated fixture currently uses a raw stream sentinel for `datagram` when Node's experimental QUIC DATAGRAM API is not exposed, so it does not prove bidirectional QUIC DATAGRAM delivery or Node status callbacks. |
| Node interop resumption scenario | Missing | The gated fixture currently labels a raw stream exchange as `resume`; it does not persist sessions across two Node/Fino connections or assert resumed/0-RTT behavior. |
| Node interop key-update scenario | Direct | `tests/net/quic-node-interop.test.mts` exercises a real key update: the Fino client calls `connection.initiateKeyUpdate()` on the Node-server path, and the Fino server calls `connection.initiateKeyUpdate()` on the Node-client path. Stream exchange completing in both directions proves the respective Node peer processed the key update without connection failure. |
| Node interop Retry scenario | Direct | The Fino listener's default address-validation policy (`sendRetry: true`) applies to all Node interop connections; the `retry` scenario confirms the Node client completes a full connection through an actual Retry packet before stream exchange. Same Retry path is exercised by the Fino server in all other interop scenarios. |
| Node interop ALPN mismatch | Direct | `tests/net/quic-node-interop.test.mts` includes a gated `alpn-mismatch` scenario in both directions and expects clean client-side failure without waiting for an accepted server stream. |
| Node interop migration and Version Negotiation | Missing | No Node interop scenario currently proves active migration or external Version Negotiation behavior; support depends on the configured Node experimental QUIC API exposing those controls. |
| HTTP/3 request/response (GET, POST, headers, binary, concurrent, errors) | Direct | `tests/net/quic-h3.test.mts` (9 tests) exercises nghttp3-backed H3 sessions over the simulated QUIC transport: GET/POST round-trips, custom headers, binary bodies, concurrent streams, 404/500 responses, and empty bodies. |
| QPACK header compression | Direct | nghttp3 handles QPACK internally; the control and QPACK encoder/decoder streams are bound and exercised in every H3 test. |
| GOAWAY, ORIGIN, H3 DATAGRAM | Out of Scope | Not yet implemented; H3 DATAGRAM requires QUIC DATAGRAM extension. |
