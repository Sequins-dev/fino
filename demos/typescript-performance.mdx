# The TypeScript data plane

<Rule />

<Lead>How Fino gets faster by pushing native code to the edges—and keeping protocols, policy, and application objects in one optimized heap.</Lead>

<Footer>V8 in the center · native at the edges</Footer>

<Notes>This is not an argument that JavaScript beats C at compression or cryptography. It is an argument about where a runtime pays coordination costs. FFI exists so TypeScript can own more of the system without asking Rust to mediate every operation.</Notes>

---

<Eyebrow>01 · The inversion</Eyebrow>

## Native is the edge, not the architecture

<div style={{ display: 'grid', gap: '.65rem', width: '100%' }}>
  <Layer label="Application" detail="Handlers, middleware, schemas, observability, workflows" tone="coral">TypeScript objects stay TypeScript objects</Layer>
  <Layer label="Protocol" detail="HTTP, DNS, Postgres, QUIC orchestration, Arrow, Parquet" tone="cyan">State machines live beside the application</Layer>
  <Layer label="Primitive" detail="syscalls, crypto, compression, nghttp2/3, ngtcp2, SQLite" tone="ink">Native code does irreducible native work</Layer>
</div>

<Callout label="Thesis">Cross once for a coarse primitive. Do the surrounding work where the data already lives.</Callout>

<Notes>The inversion is the key: the Rust host is not a second standard library. It supplies V8, loading, scheduling, isolation, and a fast path to native primitives. The TypeScript library owns the runtime behavior developers interact with.</Notes>

<Eyebrow>03 · One heap</Eyebrow>

## Staying in TypeScript removes whole categories of work

<Grid columns={2}>
  <Panel title="One object model"><div>`Request`, `Headers`, `URL`, router context, and telemetry references pass directly.</div></Panel>
  <Panel title="One optimizer" tone="amber"><div>V8 sees object shapes, monomorphic call sites, loops, and branches across the whole path.</div></Panel>
  <Panel title="One ownership regime" tone="coral"><div>Typed arrays, strings, promises, and queues do not need Rust mirrors or lifetime handoffs.</div></Panel>
  <Panel title="One debugging surface"><div>Profiles name the actual protocol and policy functions instead of stopping at a binding.</div></Panel>
</Grid>

<Notes>A native layer can only optimize what it can see. Keeping the path in TypeScript lets V8 optimize across URL parsing, Request construction, routing, and response shaping while every layer shares object identity.</Notes>

<Eyebrow>05 · What FFI is for</Eyebrow>

## The boundary is an escape hatch for primitives

<Grid columns={3}>
  <Panel title="Enter"><div>Pass scalars, pointers, and existing buffers through the V8 Fast API.</div></Panel>
  <Panel title="Work" tone="amber"><div>Let libc or a specialized library perform the operation it owns.</div></Panel>
  <Panel title="Return" tone="coral"><div>Keep bytes in place; bring back the smallest possible result.</div></Panel>
</Grid>

<Callout label="Purpose">Fast FFI does not pull the runtime into Rust. It makes a TypeScript-first runtime viable.</Callout>

<Notes>The FFI implementation still matters: fast scalar and buffer calls, stable pointer representations, and explicit ownership keep necessary crossings small. But its strategic purpose is to avoid adding a bespoke Rust binding module for every capability.</Notes>

<Eyebrow>13 · Wire protocols</Eyebrow>

## Bytes do not become faster merely because Rust reads them

<Grid columns={2}>
  <Panel title="DNS"><div>Packet encoding, compression pointers, record parsing, retries, TCP fallback, and DNSSEC policy are TypeScript over `Uint8Array` and `DataView`.</div></Panel>
  <Panel title="Postgres" tone="amber"><div>Startup, SCRAM, Parse/Bind/Execute, row descriptions, and result decoding stay in the same heap as query consumers.</div></Panel>
  <Panel title="FlatBuffers" tone="coral"><div>Schema-less table navigation returns views into existing bytes instead of native wrapper objects.</div></Panel>
  <Panel title="Formats"><div>CSV, Markdown, TOML, XML, YAML, and validation compose directly with application values.</div></Panel>
</Grid>

<Callout label="Where TS wins">Field-by-field boundary calls would cost more than the integer loads and branches they replace.</Callout>

<Notes>These modules are not automatically fast because they are TypeScript. They are fast when they scan contiguous bytes, avoid intermediate objects, and return values already shaped for their consumers. The important comparison is against a chatty native wrapper, not against an ideal native parser that never has to expose results.</Notes>

<Eyebrow>16 · Honest boundary</Eyebrow>

## TypeScript is not the right place for every loop

<Grid columns={2}>
  <Panel title="Keep native" tone="coral"><div>syscalls and readiness</div><div>TLS and cryptographic primitives</div><div>compression codecs</div><div>SQLite execution</div><div>QUIC/H2/H3 codec kernels</div></Panel>
  <Panel title="Keep TypeScript"><div>protocol orchestration</div><div>application-visible objects</div><div>routing and policy</div><div>queues, timers, cancellation</div><div>format metadata and zero-copy views</div></Panel>
</Grid>

<Callout label="Rule">Native owns compute density. TypeScript owns coordination density.</Callout>

<Notes>There are exceptions, but this rule is a better default than choosing by language reputation. Tight numerical or cryptographic loops belong in mature native libraries. Branchy orchestration over JS-visible state usually benefits from staying beside that state.</Notes>

<Eyebrow>17 · Decision rule</Eyebrow>

## Choose the side that minimizes total work

<div style={{ width: '100%' }}>
  <Decision when="A syscall or specialized kernel" choose="native edge" reason="The operating system or mature library already owns the primitive." tone="coral" />
  <Decision when="Data already lives as JS objects" choose="TypeScript" reason="Avoid mirroring object graphs and rebuilding results." />
  <Decision when="Many tiny native operations" choose="batch or lift the loop" reason="One coarse crossing beats thousands of individually fast calls." tone="amber" />
  <Decision when="State can suppress work" choose="TypeScript beside state" reason="Cache, coalesce, skip, and reuse before calling native code." />
  <Decision when="Bytes can remain bytes" choose="typed-array view" reason="Alias or slice existing storage; do not translate merely for type prestige." tone="coral" />
</div>

<Notes>Apply this per hot path, not per module. A TypeScript module can batch one native call for its core primitive, then continue in TypeScript. Profiling should decide when an abstraction or allocation leaves the hot path—not a blanket rewrite policy.</Notes>

<Eyebrow>Conclusion</Eyebrow>

# Push native code out to the edges

<Rule />

<Lead>Use native code for the work only native code should do. Keep the system around it in TypeScript—where objects, state, policy, and V8’s optimizer can see each other.</Lead>

<Footer>The boundary is infrastructure · TypeScript is the runtime</Footer>

<Notes>The surprising result is not that TypeScript outruns a native loop. It is that the end-to-end system often wins when the loop is not separated from its state and consumers by an ownership boundary.</Notes>
